You know the drift: a TypeScript type, a Rust struct, a JSON schema, a reducer, a server validator, a migration, and a wire format that is supposed to be the contract but rarely gets checked as one.

Neighbourhoods Grammars start from a different premise: the schema should be the program, and the code should be compiler output.

## The contract surface

A grammar declares records, entities, components, state machines, verbs, CRDT contracts, and presentation surfaces. The compiler emits TypeScript for the browser and Rust for the server or WASM core, with canonical wire bytes pinned by fixtures.

The result is not low-code. It is the load-bearing part written in the language designed for it, with generated code where hand-written drift usually enters.

## Runtime as a formal layer

Streaming x-machines provide the execution model. State transitions return structured results; preconditions and invariants are observable. Composition is treated as an algebraic operation, not as a convention scattered across handlers.

AI-assisted edits become tractable because the grammar constrains the search space and the emitters keep parity visible.

## Where to contribute

The developer surface includes grammar authoring, TypeScript and Rust emitters, runtime composition, CRDT bindings, identity tooling, visual editors, AI-assisted grammar scaffolding, documentation, and real community deployments.

The work is not merely application development. It is building the contract layer for a new class of groupware.
